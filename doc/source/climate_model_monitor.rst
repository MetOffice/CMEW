Climate Model Monitor proof of concept
======================================

.. include:: common.txt

This branch is an experimental port of the Climate Model Monitor (CMM),
combining the CMEW workflow and CDDS data standardisation with ESMValTool
monitoring diagnostics. The selected recipe, ``recipe_cmm``, was developed
during this project using ESMValTool's ``recipe_monitor`` as a starting
point.

Project recipe
--------------

The recipe compares two UKESM1-0-LL model runs, ``u-dr725`` and ``u-ds902``,
for 3150-3159 against CMIP6 reference data. Its diagnostics include:

* global climatology maps, including eastward wind at 200 and 500 hPa;
* annual-cycle and time-series plots, including Niño 3 and Niño 3.4 indices;
* Arctic and Antarctic climatology maps and mixed-layer-depth summaries;
* monthly sea-ice-concentration climatologies.

Branch implementation
---------------------

The Cylc graph selects ``recipe_cmm`` and runs the following main stages:

* retrieve the recipe from the configured ESMValTool installation and add the
  model-run and CMIP6 dataset definitions;
* create CDDS requests and variable lists, standardise each model run, and
  restructure the resulting files;
* run ``extract_variable_cubes`` before ESMValTool. This task keeps the
  requested timed variable from multi-cube NetCDF files, addressing an
  ESMValCore concatenation problem seen with these data;
* run the ESMValTool diagnostics.

The example compares two UKESM1-0-LL runs, ``u-dr725`` and ``u-ds902``, with
reference data. The Met Office configuration uses CDDS 4.0.4, the ``spice``
platform, and a UKESM1 conversion setup. The workflow currently pauses after
``run_recipe`` for inspection; this and the site-specific settings are
proof-of-concept choices, not portable defaults.


Files and paths
---------------

CDDS 4.0.4 and its configured software environment are required for data
standardisation. UKESM1 runs with sea-ice components also need the bespoke
model configuration files under ``$HOME/model_configs/``; these are not
provided by CMEW. See ``~jonathan.lillis/model_configs/`` for an example.

The CMM recipe file is currently stored in the ESMValTool branch mo_model_monitor_.
To enable CMEW to use this branch of ESMValTool, add the following template variables
to your ``rose-suite.conf``:

.. code-block:: ini

  [template variables]
  USE_ESMVALTOOL_BRANCH=true
  ESMVALTOOL_BRANCH="mo_model_monitor"


Automatic CMIP6 reference-data downloads
----------------------------------------

The recipe uses MPI-ESM1-2-LR and MPI-ESM1-2-HR as CMIP6 reference datasets.
To let ESMValTool retrieve missing CMIP6 files from ESGF when the recipe runs,
ensure the following values are set at the top level of the
``user_config_file_contents`` dictionary in ``configure_recipe.py``:

.. code-block:: python

  "download_dir": os.path.expandvars(esgf_download_dir),
  "search_data": "quick",


Files needed by CDDS
--------------------

In addition to the CDDS installation, this setup needs the following files
and directories. Some are generated by the workflow; the external inputs are
not supplied by this repository.

.. list-table:: CDDS inputs for the monitor example
   :header-rows: 1

   * - Input
     - Current location or source
     - Purpose
   * - Bespoke model configuration files for UKESM1.x runs with sea ice components
     - ``$HOME/model_configs/`` in ``request_defaults.yml``.
     - Provide UKESM1 model configuration to the converter.

Optional wind-variable support (``ua`` and ``zg``)
---------------------------------------------------

The test suites produce these wind fields on 17 pressure levels, while the
default MIP tables expect 19. The branch therefore includes a local MIP-table
override and a custom plugin at
``app/configure_standardise/bin/cmew_ukesm1_plugin.py``. For now, the local
mip-tables are stored in ``/data/scratch/jonathan.lillis/mip_tables/0.0.25/``.

The plugin currently supplies the ``Amon/ua`` mapping required by the active
recipe. The ``Amon/zg`` stream is listed as requiring a plugin extension, so
``zg`` support is not complete. Runs that do not request these wind variables
do not need this local MIP-table override or custom mapping plugin.
